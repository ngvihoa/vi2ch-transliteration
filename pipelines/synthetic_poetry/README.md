# Synthetic poetry pipeline

All code, configuration, tests, references, and generated artifacts for this
pipeline live in this directory. Source poems remain in `raw-collections/poem/`,
while external dependencies remain in `tools/`.

The files under `outputs/` are reproducible intermediate artifacts (synthetic
silver data), not a released train/dev/test dataset. Only a reviewed and
versioned final export should be copied into the project-level `dataset/`
directory.

```text
pipelines/synthetic_poetry/
├── scripts/       # pipeline stages and locked configuration
├── resources/     # reference mappings
├── tests/         # unit tests
├── outputs/       # generated intermediate artifacts
└── requirements-pinyin.txt
```

## 1. Normalize source poems

```bash
python pipelines/synthetic_poetry/scripts/prepare_poem_dataset.py
```

Outputs `poem_lines.jsonl`, `poem_review.jsonl`, and `poem_report.json` under
`pipelines/synthetic_poetry/outputs/` without modifying the raw poems.

## 2. Generate Vietnamese IPA

vPhon is kept as a separate GPL-licensed command-line dependency:

```bash
git clone https://github.com/kirbyj/vPhon.git tools/vPhon
git -C tools/vPhon checkout 076a5d3611d688325a71ad6dbbcd5868399bf5e7
python pipelines/synthetic_poetry/scripts/phonemize_poems.py
```

This writes `poem_ipa.jsonl` and `poem_ipa_report.json`. Historical/OCR
spellings are mapped through
`pipelines/synthetic_poetry/scripts/ipa_overrides.json`; source spellings and
phonemization forms are both retained.

## 3. Rank Pinyin candidates

Install pinned dependencies locally:

```bash
python -m pip install --target tools/pinyin-python \
  -r pipelines/synthetic_poetry/requirements-pinyin.txt
python pipelines/synthetic_poetry/scripts/map_ipa_to_pinyin.py
```

The matcher compares onset, rhyme, and Chao tone contour with respective
weights 0.35, 0.45, and 0.20. The Mandarin inventory is derived from attested
Hanzi readings in `pypinyin`; neutral-tone readings are excluded. Pinyin IPA
variants are generated by `pinyin-to-ipa`.

Outputs:

- `pipelines/synthetic_poetry/outputs/pinyin_candidates.jsonl`: deduplicated
  top-k candidate sets with
  component distances, IPA, tone, Hanzi count, and example characters;
- `pipelines/synthetic_poetry/outputs/poem_pinyin.jsonl`: line/syllable
  references to candidate sets;
- `pipelines/synthetic_poetry/outputs/pinyin_report.json`: inventory, score
  distribution, weights, and
  locked dependency metadata.

The default is twenty candidates so that the downstream transliteration
character pool has sufficient coverage. Use `--top-k N` to change it.

## 4. Select Hanzi

```bash
python pipelines/synthetic_poetry/scripts/select_hanzi.py
```

The selector reranks Hanzi with phonetic, reference-pool, and corpus-frequency
weights of 0.75, 0.15, and 0.10. Its reference pool is derived from the English
IPA table reproduced from Xinhua's *Names of the World's Peoples*. This is only
a reference character pool: Xinhua does not define it as a Vietnamese-to-Hanzi
standard. Characters outside the pool are marked as fallbacks requiring human
review.

Outputs:

- `pipelines/synthetic_poetry/outputs/hanzi_candidates.jsonl`: top Hanzi
  candidates and component scores;
- `pipelines/synthetic_poetry/outputs/poem_hanzi.jsonl`: synthetic silver poem
  lines with Hanzi and Pinyin;
- `pipelines/synthetic_poetry/outputs/hanzi_report.json`: coverage, review
  counts, provenance, and corpus
  statistics.

Character frequency is measured from the local Chinese train/dev/test corpus.
The reference mapping and its retrieval metadata are stored in
`pipelines/synthetic_poetry/resources/xinhua_english_reference.json`.

## 5. Decode with poetic rhyme constraints

```bash
python pipelines/synthetic_poetry/scripts/decode_poem_hanzi.py
```

The decoder constructs rhyme links between adjacent lục/bát and song-thất
lục-bát lines. Each connected rhyme path is optimized with Viterbi dynamic
programming over the Hanzi candidate lattice. Unlinked syllables retain their
best local candidate.

Outputs:

- `pipelines/synthetic_poetry/outputs/poem_hanzi_decoded.jsonl`: decoded
  synthetic silver lines, including candidate ranks and flags for changes from
  greedy selection;
- `pipelines/synthetic_poetry/outputs/decoder_report.json`: rhyme distance
  before/after decoding, local
  score tradeoff, total objective, change counts, and review counts.

The default pairwise rhyme weight is 0.12 and can be changed with
`--rhyme-weight`.

## 6. Quality gate and release candidates

```bash
python pipelines/synthetic_poetry/scripts/quality_gate_poems.py
```

This layer validates the decoded/source alignment and applies deterministic,
configurable line-level gates. By default, a release candidate must use no
fallback Hanzi, have an average selection score at most 0.22, have no syllable
score above 0.35, and use no decoder candidate below rank 3. These thresholds
are heuristics for triage, not calibrated probabilities or human ground truth.

Outputs remain inside the pipeline:

- `pipelines/synthetic_poetry/outputs/poem_quality_scored.jsonl`: every decoded
  line with source provenance, metrics, status, and reason codes;
- `pipelines/synthetic_poetry/outputs/poem_release_candidates.jsonl`: lines
  passing all automatic gates, still labelled synthetic silver;
- `pipelines/synthetic_poetry/outputs/poem_quality_review.jsonl`: lines needing
  human review;
- `pipelines/synthetic_poetry/outputs/quality_report.json`: thresholds,
  distributions, pass rate, and reason counts.

Use `--max-average-score`, `--max-syllable-score`, and
`--max-candidate-rank` to tune the gate. Nothing is copied to `dataset/` at
this stage.
